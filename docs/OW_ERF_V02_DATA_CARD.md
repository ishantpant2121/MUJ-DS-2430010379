# Synthetic benchmark data card — OW-ERF v0.2 pilot

## Purpose
Test an executable prototype of open-world fraud-mechanism rejection, explained-rarity filtering and typology grouping before claiming real-world validity.

## Data generation
The file **owerf_v02_benchmark.py** creates synthetic claim events with timestamps, claim features, six entity-relation keys, causal summaries from prior events, four fraud mechanisms, selectable camouflage tier, and a separate hidden evaluation-label table. The default pilot contains 2,400 records per fold and a configurable fraud-rate design parameter. Benign extreme cohorts are placed in the deployment window only (S1-style) and have a high clinical severity / documentation profile.

## What this data is not
- It is not actual insurance/patient data.
- It is not generated by Synthea.
- It does not use an official transcribed AB-PMJAY HBP 2.2 package/rate table; package rates are parametric placeholders.
- It cannot support claims of clinical validity or real-world fraud-detection performance.

## Ground truth separation
Each row has a claim ID. The model-visible feature matrix contains no mechanism label, novelty status, benign-cohort ID or scheme/ring ID. Those fields are saved separately as hidden evaluation metadata and used only after inference for metrics.

## Reproducibility
The runner records the seed, sample size, tier, hidden mechanism, split sizes, model/device, loss and evaluation metrics. The CI runner uploads per-fold reports, predictions, edges and hidden ground truth as a workflow artifact; the aggregate JSON is committed into the repository.

## Intended use
Research/software tests only. Outputs are screening hypotheses for human audit, not legal findings and not instructions to deny a claim. No real patient or claim is processed by the default synthetic pilot.
